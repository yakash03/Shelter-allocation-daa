Abstract

When a flood, cyclone or earthquake forces a region to evacuate, planners must decide which zone sends its people to which shelter, and along which roads. The problem is modelled on a weighted road network: nodes are zones (with populations), junctions and shelters (with capacities); edges are roads with travel times, some blocked.

The system is built in layers, one per syllabus unit: divide and conquer prioritises zones; greedy methods schedule buses, supplies and rescue tasks; dynamic programming selects zones for a shelter and compares routes; graph algorithms test connectivity and compute safe routes. Whole-zone allocation is shown NP-complete by reduction from PARTITION. On a ten-node test network, brute force examines 243 assignments, branch and bound finds the same optimum (13,750 person-minutes) in 25 search nodes, and the greedy heuristic finds no feasible plan.

Keywords: evacuation planning, shelter allocation, shortest path, dynamic programming, branch and bound, NP-completeness, bin packing, approximation algorithms.

Problem statement

Input. Undirected weighted graph G=(V,E,t) with travel times t(e)>0; zones Z with populations pz; shelters S with capacities cs; blocked roads B. Let n=|Z|, m=|S|, v=|V|, e=|E|.

Output. An assignment f: Z→S and a route from each zone to f(z) in G−B.

Constraints. (1) The people sent to a shelter never exceed its capacity. (2) Each zone goes to exactly one shelter. (3) Routes avoid blocked roads. (4) Total capacity ≥ total population.

Objective. Minimise Σ pz · d(z, f(z)), where d is the shortest travel time in G−B.

Basic approaches

Brute force enumerates all mn assignments, T(n)=O(n·mn); for n=30 and m=6 that is about 2.2×10²³. Greedy sorts zones by population and picks the nearest shelter with room: O(n log n + nm), fast but with no optimality guarantee, and it can fail outright.

Key analysis

Merge sort: T(n)=2T(n/2)+Θ(n) gives Θ(n log n) by Master case 2 (also shown by substitution and recursion tree). Max-Min needs 3n/2−2 comparisons. Binary search over shelters sorted by capacity finds the smallest sufficient shelter in O(log m). Dijkstra runs in O((v+e) log v). Branch and bound uses the bound cost so far + Σ pz·(distance to nearest shelter, ignoring capacity), which never overestimates, so pruning is safe.

The polynomial algorithms agree, so the routing layer is trustworthy. Whole-zone allocation is where cost grows: brute force is exponential, and the greedy rule can fail even when a plan exists (T3, T5). Branch and bound matched the brute-force optimum in every test, but its worst case stays exponential, so very large regions call for approximation or flow-based methods. T4 shows the plan must be recomputed whenever the network changes.

NP-completeness of whole-zone allocation

Whole-zone with distance costNP-hardContains SA; generalised assignment
Minimising shelters openedNP-hardBin packing

In NP. The certificate is the assignment f; a verifier computes each shelter's load in one pass and checks it against capacity in O(n+m).

NP-hard. Given positive integers a1..n with total 2B, build n zones with pi=ai and two shelters of capacity B. If a subset sums to B, send it to shelter 1 and the rest to shelter 2. Conversely, a feasible plan has both loads ≤ B and summing to 2B, so each equals B exactly, and the zones in shelter 1 form a subset of sum B. Hence SA is NP-complete (Karp, 1972).

Approximation. FFD uses at most (11/9)·OPT + 6/9 bins (Dósa, 2007). Greedy set cover gives an H(n) ≤ ln n + 1 factor (Chvátal, 1979). Approximation is not appropriate where a hard capacity rule is a safety requirement, because heuristics can fail to find any feasible plan.

Core implementation (Python 3, standard library only)

Branch and bound for whole-zone allocation. Setting bound=False gives plain backtracking.

def search(pop, cap, D, bound=True):
    zs = merge_sort(list(pop), key=lambda z: -pop[z]); ss = list(cap)
    lb = [0] * (len(zs) + 1)
    for i in range(len(zs) - 1, -1, -1):
        lb[i] = lb[i+1] + pop[zs[i]] * min(D[zs[i]][s] for s in ss)
    best, nodes, rem, asg = [INF, None], [0], dict(cap), {}
    def go(i, cost):
        nodes[0] += 1
        if bound and cost + lb[i] >= best[0]: return
        if i == len(zs):
            if cost < best[0]: best[0], best[1] = cost, dict(asg)
            return
        z = zs[i]
        for s in sorted(ss, key=lambda s: D[z][s]):
            if rem[s] >= pop[z] and D[z][s] < INF:
                rem[s] -= pop[z]; asg[z] = s
                go(i + 1, cost + pop[z] * D[z][s])
                rem[s] += pop[z]; del asg[z]
    go(0, 0)
    return best[0], best[1], nodes[0]

The full program also contains Dijkstra, BFS/DFS, Bellman-Ford, Floyd-Warshall, Prim, Kruskal, knapsack, min-cost flow, FFD and the ten-test driver.

Limitations, future work and conclusion

Limitations. Exact allocation is exponential in the worst case. Travel times are fixed, so congestion and time-varying capacity are ignored. The test network is small and hand-built; real road data is not used.

Future work. Time-expanded networks, integer linear programming and metaheuristics, live road-closure feeds on real maps, vulnerability-aware priorities (hospitals, care homes), and a web dashboard.

Conclusion. Routing, connectivity, backbones, sorting, logistics scheduling and splittable allocation are solved in polynomial time, and zone selection uses dynamic programming. The central whole-zone allocation is NP-complete, which explains why brute force scales as O(n·mn), why greedy can fail, and why branch and bound, flow relaxation and approximation are the right tools. The main lesson: match the algorithm to the class of the sub-problem.
